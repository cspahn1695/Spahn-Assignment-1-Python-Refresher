This image shows how fib(n) and the time to compute it increase somewhat (but perfectly) linearly as n increases. The spikes result from python big-integer sizing and cache growth / memory allocator behavior. You can't remove the spikes while still measuring real python fibonacci integers - since the spikes are real work being done. Additionally, it can be seen that the times to compute the fib(n) values for n = 1-100 are much smaller than in the example provided with the assignment. It is likely the example graph provided with the assignment didn't using caching. The overall trend is that fib(n) increases somewhat linearly for n from 0-70. There still looks to be an increase in fib(n) after n=70, but this region has many more spikes.
